### Root cause

The highlighted variant’s inset spread shadow (`0 0 0 2px #bfdbfe inset` on root `ContentListBoard`) is extracted correctly but **not reproduced in live Figma export** — the blue highlight ring is missing (red diff along the left card edge in `diff.png`), while mock/pixel pass because mock replay applies Storybook CSS from the effect metadata.

### Recommended fix area

1. Verify `effectsFromPaint` assigns `INNER_SHADOW` with `spread: 2` when `clipsContent === true` on root (see `shouldClipContent` / `hasSpreadShadow` ~L2930–2955).
2. Ensure post-border logic (~L3733–3740) does **not** clear `clipsContent` when the layer has inset/spread shadows (extend `frameRequiresClipContent` or equivalent guard).
3. If Figma live still under-renders spread inner shadows on rounded frames, synthesize the highlight as an inner stroke or SVG ring overlay (same pattern as `applyBorders` / `buildBorderOutlineSvg`) when `classList` includes `highlighted` or shadow signature matches inset spread ≥2.

### Root cause

Figma showed extra blue at y=0 and along the left perimeter (region-01/04), while Storybook’s ring sits at 1–3px inside the outer edge.

### Recommended fix area

### Fix applied

- Added `maxBorderWidth`; ring geometry: outer at `(borderW, borderW, w-2·borderW, h-2·borderW)`, inner hole +`spread`, radii `r - borderW` / `r - borderW - spread`.
- `applyInsetSpreadRingOverlay`: clear vector group fills (match `__border`).
